# RAIN POKER PUB

모바일 우선 홀덤펍 타이쿤 웹게임.

## 현재 구현된 첫 플레이

- Supabase 이메일 계정 생성 / 로그인
- 로그인 계정별 `game_saves` 서버 세이브
- 펍 이름 최초 1회 설정
- 15×18 실제 타일맵 첫 매장
- 시작 시 테이블 0 / 딜러 0 / 손님 0
- 하단 네비 없이 플로팅 메뉴 사용
- 건설 → 기본 포커 테이블 실제 타일 배치
- 직원 → 딜러 / 서빙 직군 분리
- 기본 모집 → 일반 딜러만 등장
- 일반 딜러를 실제 테이블에 배치
- 영업 시작 → 1주차 월요일
- 실제 손님 생성 → 입구 등장 → 빈 좌석까지 타일 경로 이동 → 착석
- 중요 행동 즉시 저장 + 진행 중 자동 저장 + 화면 이탈 시 저장 시도
- 재로그인 시 서버 세이브 이어하기

## 첫 매장 공간 기준

기본 테이블 모듈:

- ㅁ: 통로/빈 바닥
- ㅅ: 손님 1명 점유 칸
- ㄷ: 딜러 1명 점유 칸
- ㅌ: 테이블 본체 점유 칸

```text
ㅁㅁㅁㅁㅁㅁㅁ
ㅁㅁㅅㄷㅅㅁㅁ
ㅁㅅㅌㅌㅌㅅㅁ
ㅁㅅㅅㅅㅅㅅㅁ
```

테이블 하나는 손님 9명 + 딜러 1명을 수용한다. 첫 매장은 외벽 포함 15×18, 실사용 내부 13×16이며 최대 4개의 풀 테이블과 이후 소파/편의시설 영역을 고려한다. 통로 타일은 테이블 모듈끼리 공유할 수 있지만 좌석/딜러/테이블 본체 점유 칸은 겹칠 수 없다.

## 직원 v0.1

직군과 직원 타입, 모집 방식은 분리한다.

- 직군: 딜러 / 서빙
- 직원 타입: 일반 딜러부터 시작
- 모집 방식: 기본 모집만 실제 활성
- 기본 모집 결과: 일반 딜러
- 특별 모집/가챠: 후속 시스템
- 서빙: 메뉴 구조는 존재하지만 아직 모집 가능한 직원 없음

첫 튜토리얼에서는 경제 밸런스를 임의로 만들지 않기 위해 스타터 테이블 1회와 기본 모집 1회를 제공한다. 추가 구매 가격과 일반 모집 비용은 경제 시스템 확정 단계에서 연결한다.

## 계정 / 저장 보안

Supabase Auth와 Postgres를 사용한다. 공개 웹 클라이언트에는 publishable key만 사용하며, `service_role` 키나 DB 비밀번호를 포함하지 않는다.

`public.game_saves`는 Row Level Security가 활성화되어 있고 로그인한 사용자는 자신의 `user_id` 행만 읽고 만들고 수정하고 삭제할 수 있다.

Production Supabase project: `RAINPOKERPUB` (Seoul region).
